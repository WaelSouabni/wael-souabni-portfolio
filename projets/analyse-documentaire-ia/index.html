Analyse de documents par IA

Relier une GED à un service d’analyse documentaire par IA dans un flux métier d’assurance.

Contexte du projet

Dans le contexte de Carene Digital, j’ai travaillé sur l’intégration d’un flux d’analyse documentaire destiné à automatiser une partie de la lecture des documents utilisés dans les dossiers d’assurance. Le travail relie la récupération du document, une API applicative et un service de traitement documentaire.

Le défi

L’analyse ne commence pas par un fichier arbitraire : il faut retrouver le bon document dans la GED en tenant compte du devis et du tenant courant, puis exposer le traitement à travers une interface API intégrable au produit.

Approche technique

Le flux s’appuie sur l’endpoint `POST /api/ocr/analyze`. L’application retrouve le document dans la GED Veos selon le contexte du devis et du tenant, puis intègre Mistral Document via Azure AI Foundry. L’API sert de point d’entrée au traitement depuis le reste de l’application.

Ma contribution

  • Conception et intégration de l’endpoint `POST /api/ocr/analyze`.
  • Connexion au flux de récupération documentaire de la GED Veos.
  • Intégration de Mistral Document via Azure AI Foundry.
  • Prise en compte du contexte devis/tenant dans le flux applicatif.
  • Documentation du fonctionnement à un niveau compatible avec la confidentialité du projet.

Technologies

  • TypeScript
  • NestJS
  • REST API
  • Mistral Document
  • Azure AI Foundry
  • GED Veos

Objectif et bilan

L’objectif fonctionnel est de réduire les manipulations manuelles liées à la lecture des documents. Aucun chiffre de précision, de gain de temps ou de volume n’est publié ici, car je ne dispose pas de métriques publiques vérifiables.
